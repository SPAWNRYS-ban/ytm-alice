# Локальный стенд kuyase

Стенд запускает настоящие Linux-прошивки Станций в QEMU через
[kuyase 1.4.0](https://github.com/vypivshiy/kuyase/releases/tag/1.4.0).
Команды ниже выполняются из корня ytm-alice. Нужны Linux с пользовательским
systemd, Python 3.11+, QEMU AArch64, ADB, e2fsprogs, tar с zstd;
для аудиотеста нужен ffmpeg. Root не требуется.

```sh
python3 tools/kuyase/lab.py bootstrap
python3 tools/kuyase/lab.py list
```

`bootstrap` скачивает portable-релиз и проверяет SHA-256 по файлу релиза.
Все скачанные файлы, образы, диски данных и отчёты находятся в
`.build/kuyase-lab/`, который исключён из Git. Путь можно переопределить
через `YTM_KUYASE_HOME`.

## Образы и модели

Источник готовых образов — [тема с прошивками](https://t.me/c/4457409211/1514).
Каталог `tools/kuyase/models.json` содержит сообщения с образами 12 моделей.
Доступ к теме требует членства в группе Telegram. Скачайте архив выбранной
модели и импортируйте его:

```sh
python3 tools/kuyase/lab.py import yandexmicro /путь/yandexmicro-system.tar.gz
```

Принимаются готовые `.ext4` и архивы с одним системным `.ext4`. Импорт
проверяет файловую систему, сохраняет источник и SHA-256 архива в `images.json`.
Существующий системный образ не перезаписывается. Для исходных дампов
rootfs/UBI сначала используйте `kuyase prepare --dump ...` согласно документации
эмулятора. Android/YaOS-модели kuyase не поддерживает.

## Запуск и загрузка приложения

```sh
python3 tools/kuyase/lab.py start yandexmicro
python3 tools/kuyase/lab.py deploy yandexmicro /путь/ytm-alice-0.7.4-yandexmicro.yampkg
python3 tools/kuyase/lab.py status
python3 tools/kuyase/lab.py shell yandexmicro 'cat /tmp/ytm-alice.log'
python3 tools/kuyase/lab.py smoke yandexmicro
python3 tools/kuyase/lab.py stop yandexmicro
```

`start all`, `stop all`, `smoke all` работают со всеми импортированными моделями.
`python3 tools/kuyase/lab.py report` собирает таблицу последних результатов
в `.build/kuyase-lab/reports/matrix.md` и сводный `summary.json`.
Каждая ВМ — отдельная временная служба `ytm-kuyase-<профиль>.service`, 2 vCPU
и 512 МиБ RAM. Службы не включаются в автозапуск компьютера. Все порты
привязаны к `127.0.0.1`; отдельный TAP и настройка роутера не нужны.

Системный образ запускается со snapshot. У каждой модели свой постоянный
диск `/data` размером 512 МиБ; файлы приложения лежат в `/data/ytm-lab`.
При следующем `start` контроллер запускает уже загруженное приложение.
Останавливайте ВМ через `lab.py stop`: контроллер вызывает гостевой `sync`
перед завершением QEMU, чтобы сохранить последние записи в `/data`.
`start <модель> --clean` использует временный `/data`; установленные туда
файлы исчезнут после остановки ВМ.

`deploy` извлекает из указанного пакета бинарники приложения, включая оба
варианта нативного плеера при их наличии, сверяет
SHA-256 после передачи по ADB и запускает демон. Это проверка среды выполнения:
проверка ограничений платформы пакета YAM и его установка/обновление/удаление
остаются отдельными сценариями. Пакеты будущего релиза используют общий набор бинарников: запускатель
выбирает ARM32/ARM64 по библиотеке GStreamer прошивки. Старые пакеты с одним
ARM32-плеером также принимаются для сравнительных проверок.

Для повторного тестирования новой сборки снова выполните `deploy`.
Пользовательские данные предыдущего запуска сохраняются. Новая установка
получает веб-порт `8090` внутри ВМ (штатный проброс kuyase), отключённые
cast, радио и LED, пустую фразу анонса. Эти параметры уменьшают влияние
посторонних служб на тест; при проверке конкретной функции включайте её явно.
Cookies и аккаунт настоящей колонки не копируются.

## Проверки и ограничения

`smoke` сохраняет JSON в `.build/kuyase-lab/reports/<профиль>.json` и возвращает
ненулевой код при любой ошибке. В отчёте раздельно отражены:

- сведения о прошивке и эмулируемая ALSA-карта;
- версия приложения и ответ локального CLI;
- HTTP API панели: `/api/info`, `/api/state`;
- нативное воспроизведение локального AAC-файла через GStreamer/ALSA;
- TTS через локальный IPC;
- настоящий `StateSnapshot` аппаратного моста, включая счётчики ошибок IPC и LED.

Аудиотест генерирует четырёхсекундный тон на хосте и временно обслуживает
его через отдельный статический BusyBox httpd внутри ВМ. Помощник скачивается
с официального busybox.net, проверяется по закреплённому SHA-256 и работает
из `/tmp/ytm-fixture`; системный BusyBox прошивки не заменяется. Он проверяет декодирование AAC, переход
плеера в `playing` и продвижение позиции. Это не проверка слышимости на
физическом динамике и не проверка получения потока YouTube.

Для встроенных проверок самого эмулятора сначала остановите выбранную ВМ:

```sh
python3 tools/kuyase/lab.py stop yandexmicro
python3 tools/kuyase/lab.py test yandexmicro
python3 tools/kuyase/lab.py start yandexmicro
python3 tools/kuyase/lab.py logs yandexmicro
```

Kuyase работает в режиме `stub`: ALSA и локальный IPC эмулируются, облачная
Алиса, Wi-Fi/Bluetooth, Zigbee и DSP не воспроизводятся полностью. Успешные
проверки запуска и панели не доказывают работу облачных голосовых команд,
трансляции из LAN или YouTube. Авторизация YouTube и внешняя сеть проверяются
отдельно; прошивки и ключи реальной Станции стенд не изменяет.

Полная очистка стенда требует сначала `stop all`. Затем можно удалить
`.build/kuyase-lab/`; при этом исчезнут образы и все тестовые аккаунты,
настройки и очереди. Код в `tools/kuyase/` и эта инструкция сохранятся.

## Результаты проверок

Полная таблица по 12 моделям находится в [KUYASE-MATRIX.md](KUYASE-MATRIX.md).
Базовый прогон выполнен с релизом 0.7.4 (`ca93afe`). Текущий кандидат
с исправлением #13 и общим медиаслоем находится в `.build/candidate-final/`;
его происхождение и SHA-256 бинарников указаны в `build.json`, пакетов —
в `SHA256SUMS`. Версия в приложении пока остаётся 0.7.4; это локальная
сборка, а не опубликованный релиз. Источники и SHA-256 всех образов хранятся в
`.build/kuyase-lab/images.json`.

Детальные отчёты приложения: `.build/kuyase-lab/reports/<профиль>.json`.
Логи самотестов: `.build/kuyase-lab/test-*.log`. Результаты перезапуска
исходных четырёх моделей находятся в `reports/lifecycle.json`, восьми
добавленных — в `reports/expansion.json`. Команда `lab.py report` собирает
общую таблицу и JSON из этих файлов.

При проверке перезапуска контролируются данные и настройки в `/data`,
исчезновение временного файла из корневой системы и неизменность SHA-256
базового образа. После запуска приложение должно снова отвечать.

Разрядность прошивки определяйте по ELF-заголовкам её файлов, а не по
`uname -m`: у всех ВМ ядро AArch64, но многие прошивки используют ARM32.
Например, в импортированном образе Миди `busybox`, `maind` и
`libquasar_gstreamer.so` имеют ELF32, хотя README kuyase обозначает её
как aarch64. В Мини 3 Про и Станции 3 это ELF64 и имеется только
`/lib/ld-linux-aarch64.so.1`: ARM32-плеер релиза 0.7.4 выдаёт `not found`, хотя
файл существует. В текущем кандидате это исправлено: общий пакет содержит
плееры обоих ABI, запускатель выбирает нужный по библиотеке прошивки.
AAC воспроизводится на всех 12 моделях стенда.

Тайм-аут TTS фиксируется отдельно от успешного воспроизведения AAC:
мост может принять `START_VOCALIZE` и текст, но приложение не получает
ожидаемого подтверждения завершения. Поэтому `smoke` возвращает код 1
при такой ошибке даже с работающими CLI, HTTP и AAC. Это результат
взаимодействия с заглушкой, который не заменяет проверку настоящей колонки.
