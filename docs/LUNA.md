# Интеграция с Luna

Экспериментальная версия 0.8.0-luna.1. Публичный релиз 0.7.1 остаётся вариантом отката.
Нужна доработанная Luna 0.2.7 из комплекта этого pre-release:
поддержка бинарных плагинов YAM, namespace в runtime API и отключённые
автообновления при первом запуске. Патч к закреплённой ревизии upstream и
инструкция сборки находятся в [source/luna-host](../source/luna-host/README.md).

## Установка

Используйте пакеты Luna и ytm-alice из одного тестового набора для своей модели.
Для сборки Luna после компиляции station binary используйте
`tools/package-station.sh MODEL OUTPUT.yampkg` в её репозитории. Путь к host YAM
и профилям можно задать через `YAM_BIN` и `YAM_PROFILES`.

```sh
yam install --yes luna-0.2.7-ytm-yandexmicro.yampkg
/data/yam/bin/luna-service install
/data/yam/bin/luna-service start
yam install --yes ytm-alice-0.8.0-luna.1-yandexmicro.yampkg
/data/yam/bin/ytm-alice daemon install
```

Перед обновлением работающего ytm-alice выполните `ytm-alice daemon stop`.
`daemon install` включает плагин в Luna и убирает прежний автозапуск ytm-alice.
YAM хранит пакет, Luna запускает процесс и его помощников. Сессия и очередь
сохраняются в `/data/yam/var/local.ytm-alice`. Резервные копии храните на компьютере,
не на Станции.

Панель остаётся на `http://alice.lan` или `http://IP_СТАНЦИИ`; API Luna слушает
только loopback, порт 8099. CLI и подключение аккаунта остаются прежними.

Повторная установка той же версии через YAM не поддерживается. Для замены
тестовой сборки остановите сервис, удалите пакет и установите новый файл той же
версии. YAM сохраняет данные в `var`; не удаляйте их вручную.

Для отката остановите ytm-alice, выполните `luna-service uninstall`, удалите
`local/ytm-alice`, установите прежний пакет 0.7.1 и выполните
`ytm-alice daemon install`. Luna останется установленной, но её init-hook будет
снят. Сессия и очередь сохраняются.

## Границы

- `engine.go`: GStreamer, наблюдаемое состояние и завершение helper-процессов.
- `luna.go`: выбор источника, выполнение команд провайдера, heartbeat и
  подтверждение результата. Поиск и подготовка URL идут до команды Luna.
- `voice.go`: специализированные команды YouTube Music, прежний адаптер событий речи,
  приглушение музыки и сохранение штатных запросов Алисы.
- `service.go`: один foreground-процесс, завершение аудио при SIGTERM.
- Каталог, cookies, аккаунты, очередь, HTTP-панель и CLI остаются в Go.

Пауза подтверждается событием GStreamer или завершением процесса. Новый источник
выбирается после подтверждённой паузы. Команда провайдера с просроченным результатом
не должна продолжать подготовку и внезапно запускать музыку.

## Ограничения прототипа

- bt-proxy и MPRIS пока входят в пакет: Luna сама физическую кнопку не перехватывает.
  Transport-команды идут через выбранного провайдера Luna.
- События речи и отмена диалога пока используют прежний адаптер IPC. Новый
  голосовой путь Luna отключён после сбоя на тестовой Станции; перенос этого
  участка требует отдельной проверки протокола конкретной прошивки.
- «Включаю» и название трека озвучиваются прежним адаптером штатного TTS:
  готового TTS API Luna пока нет.
- Штатный музыкальный плеер ещё не зарегистрирован провайдером. При команде
  «включи музыку» ytm-alice уступает ему воспроизведение прежним способом.
- Другие AirPlay/Spotify-пакеты должны реализовать протокол провайдера, чтобы Luna
  могла координировать их. Само наличие пакета не добавляет адаптер автоматически.
- Общий API Luna не добавляет поддержку аудиобиблиотек новых моделей. Пакеты
  по-прежнему собираются для `yandexmicro` и `yandexmini_2`.

## Проверки

```sh
cd source
go test -race ./...
python3 -m unittest discover -s . -p 'test_*.py'
```

Проверка Luna: `cargo test --workspace --locked`, затем
`python3 tests/yam_binary_http.py target/debug/luna` и
`python3 tests/media_provider_http.py target/debug/luna`.
На устройстве отдельно проверяются звук, голос, физическая кнопка и reboot.
Автозапуск Luna с пустым временным каталогом проверяется командой
`python3 tests/yam_service.py target/debug/luna` в её репозитории.
