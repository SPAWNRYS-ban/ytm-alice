# Веб-панель ytm-alice

Панель встроена в ytm-alice. CLI/TUI и голосовые команды
работают параллельно с ней.

Панель входит в тот же пакет local/ytm-alice и работает на колонке.
Нужен только YAM v2. Старый YAM/yamd и его веб-панель не используются.
Адрес панели — http://alice.lan:24721, с доступом по IP для сетей без такого
DNS-имени. Импорт cookies выполняется в этой же HTTP-панели.
Домен alice.lan настраивается в локальной сети пользователя, установка
пакета сама по себе не создаёт запись в DNS роутера.

## Вход по коду (YouTube TV)

Кнопка «Войти по коду» показывает код и адрес google.com/device. Код вводится
на телефоне или компьютере, там же выбирается аккаунт Google. Колонка ждёт
подтверждения в фоне и сохраняет refresh-токен приложения YouTube TV
в youtube-session.json с правами 600. В отличие от cookies, он не ротируется
браузером и действует, пока доступ не отозван в аккаунте Google
(«Сторонние приложения» → YouTube on TV).

Внутренний API YouTube принимает токены только собственных клиентов Google,
поэтому id и секрет клиента читаются из публичного скрипта youtube.com/tv
(так же делает SmartTube). Если YouTube изменит страницу, вход по коду станет
недоступен; cookies продолжат работать.

Что работает при входе по коду: лайки YouTube Music (VLLM) с подгрузкой всех
страниц, плейлисты библиотеки, радио, проверка аккаунта. Запросы идут
клиентом TVHTML5 на www.youtube.com: клиент YouTube Music отвечает HTTP 400 на
токены TV. Поиск, альбомы и воспроизведение остаются публичными. Главной
YouTube Music у клиента TV нет, поэтому рекомендации — радио от последнего лайка.
Смена профиля недоступна: аккаунт выбирается на странице Google при вводе кода.

## Подключение YouTube Music через браузер

В настройках есть раздел «YouTube Music» с инструкцией и выбором файла.
CLI для обычного импорта через этот раздел не требуется.

Порядок действий пользователя:

1. Установить расширение для экспорта Netscape cookies.txt:
   [cookies.txt для Firefox](https://addons.mozilla.org/en-US/firefox/addon/cookies-txt/)
   или [Get cookies.txt LOCALLY](https://github.com/kairi003/Get-cookies.txt-LOCALLY).
   Разрешить расширению работу в приватном окне.
2. В отдельном приватном окне войти в нужный аккаунт YouTube Music.
3. В той же вкладке открыть https://www.youtube.com/robots.txt и экспортировать
   cookies YouTube в формате Netscape. Выбрать Export, а не Export All Cookies.
4. Закрыть приватное окно без выхода из аккаунта. Такой способ уменьшает
   вероятность ротации cookies из-за активной вкладки YouTube; постоянный вход
   не гарантируется. [Рекомендации yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies).
5. В панели выбрать cookies.txt и нажать «Показать аккаунты».
6. Выбрать профиль по имени и названию канала, затем нажать
   «Подключить выбранный профиль». Лайки и плейлисты загружаются для этого профиля.

«Сменить профиль» получает список профилей сохранённой сессии без нового файла.
Текущий профиль отмечен в списке. Недоступные профили выбрать нельзя.
Если сессия истекла, панель сообщает об этом и предлагает загрузить свежий файл;
само наличие файла на колонке не считается подтверждением входа.

Интерфейс различает состояния: аккаунт не подключён, идёт проверка, подключён,
сессия требует обновления, ошибка сети и неверный формат файла.
Обновление сессии повторяет импорт. Кнопка «Отключить аккаунт» удаляет
сохранённую копию с колонки; браузер пользователя остаётся авторизованным.

## Требования к импорту

- Поддержать Netscape cookies.txt, включая строки с префиксом #HttpOnly_.
  [Описание формата](https://curl.se/docs/http-cookies.html).
- До передачи на колонку разобрать файл в браузере и оставить только точный
  список разрешённых доменов YouTube из текущего клиента: .youtube.com,
  youtube.com, .music.youtube.com, music.youtube.com и www.youtube.com.
  Остальные cookies не передавать и не сохранять.
- Ограничить размер файла и запроса. Не сохранять исходный загруженный файл
  на колонке, не показывать значения cookies в интерфейсе и журналах.
- Использовать существующую проверку auth-import и проверять вход до замены
  прежней сессии. Неудачный импорт сохраняет прежнюю рабочую авторизацию.
- Сохранять только сессию YouTube, индекс Google-аккаунта и идентификатор
  выбранного канала, с правами 600. Ссылки входа и служебные токены
  из ответа со списком профилей не передаются интерфейсу.
- По решению владельца локальная панель доступна без пароля и сопряжения.
  Команды защищены проверками Host, Origin, JSON Content-Type и отдельного
  заголовка; произвольные внешние сайты не могут выполнять команды панели.
- По решению владельца все функции, включая импорт cookies, работают
  по HTTP внутри доверенной локальной сети. HTTPS и сертификаты не нужны.
- В инструкции пояснить, что cookies дают доступ к сессии аккаунта,
  и предложить удалить экспортированный файл после успешного подключения.

Текущая авторизация применяется к библиотеке, лайкам и резервному запросу
аудиопотока для треков, требующих входа/подтверждения возраста. Cookies
передаются только API music.youtube.com; декодер подписей и CDN их не получают.
Она не обещает
Premium-возможности или доступ к закрытым видео. Истечение сессии не должно
блокировать публичный поиск и воспроизведение доступных треков.

## Обложки

Клиент и колонка предполагаются в одной локальной сети с общим сетевым
обходом. Обложки загружает браузер напрямую с серверов изображений YouTube.
Сервер ytm-alice извлекает HTTPS-ссылки из метаданных треков и плейлистов
и передаёт их клиенту в поле thumbnail_url.

Трафик изображений идёт между браузером и серверами изображений;
колонка не скачивает, не проксирует и не кэширует сами картинки.
Кэшированием управляет браузер. Изображения в списках загружаются по мере
появления на экране; для главного плеера выбирается доступная обложка
подходящего размера.

Если адрес отсутствует или изображение не загрузилось, клиент показывает
заглушку. Загрузка обложек не задерживает начало воспроизведения.
Очереди, сохранённые до появления thumbnail_url, остаются совместимыми;
для них используется ссылка на стандартное превью по ID видео.

## Остальная панель

Доступны: адаптивный плеер, поиск, очередь, лайки, плейлисты и настройки
озвучивания. Веб-панель, CLI и голос используют общий обработчик команд.
Закрытие страницы не останавливает музыку. В панели нет произвольного
shell-доступа или установки сторонних пакетов.

## Развёртывание и ресурсы

HTML/CSS/JS встроены в Go-бинарник; отдельного процесса или runtime нет.
Новые установки используют 24721/TCP; при обновлении прежний порт 80 сохраняется.
Постоянный адрес задаётся в настройках или `ytm-alice config set web_addr :24721`
и применяется после `ytm-alice daemon restart`. Для разработки адрес можно переопределить
через YTM_ALICE_WEB_ADDR; значение off отключает веб-панель. Занятый порт не останавливает музыкальный сервис:
ошибка доступна в /tmp/ytm-alice.log.

Статус обновляется раз в 3 секунды только при видимой странице.
Сессия остаётся в var/local.ytm-alice вне пакета и сохраняется при обновлении.
Пакет не устанавливает старый YAM/yamd.
